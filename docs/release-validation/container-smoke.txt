Three release blockers found and fixed while running this gate
--------------------------------------------------------------
1. `pnpm --filter web build` failed at prerender:
   `useSearchParams() should be wrapped in a suspense boundary at page "/login"`.
   Next 16 refuses to prerender that route. Fixed in dc8a78c by moving the form
   into `LoginForm` behind a `<Suspense>` boundary.
2. The web Dockerfile's final step failed:
   `COPY --from=builder /app/apps/web/public ./apps/web/public` ->
   `"/app/apps/web/public": not found`. Fixed in ad25111 by adding the missing
   `apps/web/public/.gitkeep`.
3. `deploy/compose.test.yml` published PocketBase's port 13090, but Docker
   silently drops published ports for a container attached only to an
   `internal: true` network (production `backend` is internal), so the port was
   never bound and the smoke timed out at `ready(${pbUrl}/api/health)`. This was
   reproduced in isolation (docker 29.1.3): internal-only ->
   `NetworkSettings.Ports = {"80/tcp":null}`; after attaching any non-internal
   network -> port bound and reachable. Fixed in ad9368e with a test-only
   `probe` bridge network for PocketBase; `web` and `gateway` still never join
   a network that can reach PocketBase directly.

Before the fixes, neither the CI `check` job (web build) nor the CI `containers`
job could pass; both were still unexecuted on GitHub, so this had not been
observed.
