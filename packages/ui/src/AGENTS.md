## OVERVIEW

Shared UI component library for all dBrain applications. Combines shadcn/ui primitives with custom application-specific components. Largest UI package.

## STRUCTURE

```
components/
├── ui/              # Base shadcn components (DO NOT modify)
├── header/          # App headers (graph-header, editor-header)
├── preview-block/    # Node preview renderers (PreviewBlock hover panel +
│                     #   NodePreviewCover, the media-only cover the gallery reuses)
├── pdf-viewer/       # Self-drawn PDF viewer (pdfjs + TextLayer + find + rail);
│                     #   `<PdfViewer>` replaces the browser plugin in pdf nodes
├── annotation/       # Handwriting layer over a base surface: pure `geometry.ts`
│                     #   / `draw.ts` / `recognizer.ts`, the `annotation-canvas.tsx`
│                     #   pointer state machine, the toolbar and the layer
├── pan-zoom/         # The **shared viewport transform** (`transform.ts` pure
│                     #   maths, `use-pan-zoom.ts` controller) that keeps a base
│                     #   surface and the annotation layer on it pixel-identical,
│                     #   plus the host-agnostic `<PanZoomResetButton>` /
│                     #   `<PanZoomResetPill>`
├── video-player/     # HLS-aware <VideoPlayer> (hls.js, loaded lazily)
├── footer/          # App footers
└── *.tsx            # Custom components (KnowledgeGraph, etc.)
utils/
├── cn.ts            # Tailwind class merger (ALWAYS use this)
├── *.ts             # Other utilities
hooks/               # Component-specific React hooks
styles/
└── globals.css      # Global Tailwind styles
```

`components/ui/` currently ships: alert, badge, button, calendar, card, checkbox,
collapsible, command, context-menu, dialog, dropdown-menu, input, input-group,
label, popover, scroll-area, select, separator, sheet, sidebar, skeleton, slider,
switch, tabs, textarea, toggle, toggle-group, tooltip. `calendar` wraps
`react-day-picker` (the shadcn default) and is the date editor every dataview DOM
surface uses. All are built on the single `radix-ui`
package (not per-primitive `@radix-ui/react-*`), so a new primitive is a local
file importing `{ X as XPrimitive } from "radix-ui"`.

`globals.css` carries the Tailwind `@source` list. A workspace package reached
through a `node_modules` symlink is **not** auto-scanned, so its source must be
listed there (`@workspace/dataview` is) or every class used only by that package
silently disappears.

| PDF viewing       | components/pdf-viewer/    | `<PdfViewer>` — pdfjs on `<canvas>` + an invisible `TextLayer` (selection, `Ctrl/Cmd+F` search), eight layouts (垂直/水平 × 连续/翻页 × 单页/双页), thumbnails + outline rail, 下载/新标签页, and the pdf's ink layer (`annotations` / `onAnnotationsChange` / `compact`). Zoom keeps **two multipliers** on purpose — the page box follows a gesture while the canvas bitmap lags and is stretched (`pdfZoomRaster` in `types.ts` is the policy) — because re-painting pdfjs per wheel notch cancelled the render the notch before it had started; do not collapse them back into one. Its viewport is **not** a CSS transform (it is a scroller: 平移 = scroll, 缩放 = page-box multiplier + `anchorScroll`), so the pdf owns its own touch gestures on the scroller — 1 finger pans, 2 pinch (`pdfPinchFrame`), 1-finger double tap resets to the opening view — and reuses only `pan-zoom/recognizer.ts` + `PanZoomResetPill`. `touch-action: none` on the scroller is load-bearing (the ink canvases need it for the pen; mixing it with native panning would give one document two different feels) and costs inertia. The layer is mounted with `arbitrateViewport` (it arbitrates palm/multi-finger but never drives the viewport) and `pointerToggle` (the 批注/浏览 switch: 浏览 gives each page's pointers back to the text layer so a passage can be selected, while pan/pinch keep working — only safe because they live on the scroller). It hands the annotation layer one `AnnotationSurface` per **visible** page box (`getSurfaces` + `surfacesKey`), so the ink is portaled into the page and cannot drift; each page canvas self-measures at `pointerdown` (`selfMeasured`). **One density budget serves paper and ink**: `pdfRasterDpr` (with `PDF_MAX_PIXELS` = 4096²) prices a page bitmap by _area_, not only by ratio, and the viewer hands the ink layer the same budget as `maxPixels` — without it a page at 6× is a 70 MP canvas whose allocation fails (the budget is _per surface_; a page holds up to three). `surfacesKey` carries **`effectiveScale` too**, so the layer re-measures inside the commit that resized the boxes (before paint) and a canvas pinned to its box is never stretched for a frame — the ink no longer shimmers while zooming. A page canvas is `alpha: true` on purpose: `release()` drops the store to 1×1, and on an `alpha: false` context that 1×1 is opaque black stretched over the whole page — the `getContext → null` case is a _transparent_ blank instead — and the loading placeholder is a fixed light tint rather than `Skeleton`'s theme-coloured `bg-muted`, which in the dark theme was itself a black pulsing page. The strip centres a possibly **overflowing** page with `m-auto` on the row, never `justify-center` (unsafe centring puts half the overflow before the scroll origin, i.e. out of reach — "can't scroll to the page's left edge once zoomed past the viewport"), and the render-ahead `rootMargin` goes on the axis the strip runs along. pdfjs is a **dynamic** import and each document builds its own worker; the toolbar is presentational (`PdfToolbarProps` in/out). `pdf-node-content.tsx` hosts it, persists `annotations` through the shared writer, and keeps the old `<iframe>` for the failure path |
| Annotation        | components/annotation/    | `<AnnotationLayer items onItemsChange getBaseRect getSurfaces panZoom />` over **any** base. Host-agnostic by contract: it never reads a store and never learns who its host is. Two geometries: a **single surface** (image) takes the base rectangle as a **transformed** viewport rect from `getBaseRect()` and paints one canvas in the layer root; a **paginated** base (pdf) names its page elements through `getSurfaces()` and gets one canvas **portaled into each page box** — the ink is a DOM child of the page, so scroll/zoom overlap is structural, and the layer stamps `Annotation.page` from the surface a gesture happened on. `surfacesKey` is how a newly mounted page is announced (a `ResizeObserver` cannot see an element it has never been handed) **and** how a host announces that the surfaces it already handed over just moved or resized: the layer re-measures in a **layout** effect, so a canvas pinned to its box (explicit `100%`, never `width: auto` on a replaced element) is resized in the same paint — never stretched for a frame (the pdf puts its multiplier in the key). The observer is created once and re-pointed by each measurement rather than rebuilt per key, or a host that announces every zoom step would pay an initial notification per page per frame. `maxDpr` / `maxPixels` bound the ink's raster: the pixel budget is priced against the canvas element's own box, and a host passes the same number its base uses (`PDF_MAX_PIXELS`), so paper and ink stay one density. Pure modules (`geometry.ts`, `draw.ts`, `recognizer.ts`) are exercised by `pnpm --filter=@workspace/ui test`; `use-annotation-input.ts` is the only pointer state machine and owns pen-vs-touch, palm rejection, pinch arbitration and the multi-finger taps. It is the **pointer target** for the whole host, so it is also where an image host's viewport gestures are recognised — a pdf host keeps them on its scroller instead, because a page canvas cannot see a finger in the gutter (it passes `arbitrateViewport` so the layer keeps the palm/multi-finger half — those taps exist in 批注 mode only, since 浏览 mode makes the canvas inert — and `onResetView` so the `0` key works). A portaled page canvas keeps its keyboard shortcuts without any extra listener — React dispatches synthetic events along the **React** tree, so the root's `onKeyDown` sees a canvas that lives in a page box (adding a document-level bridge fired every shortcut twice)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## CONVENTIONS

- **Named exports only** — no default exports
- **Always use `cn()`** from `@workspace/ui/utils/cn` for class merging
- **Filename = Component name** in PascalCase (e.g., `KnowledgeGraph.tsx`)
- **Props interfaces** extend native HTML element types
- **Tailwind v4 ordering**: base → layout → components → utilities
- **Dark mode** via `dark:` prefix only — no custom CSS color variables
- shadcn components in `components/ui/` are base — extend in custom components

## ANTI-PATTERNS

- **NEVER** inline custom CSS when Tailwind utility exists
- **NEVER** modify shadcn base components after adding — extend instead
- **NEVER** duplicate components — extend or compose
- **NEVER** forget `cn()` even when no conditional classes
- **NEVER** add third-party component libraries when shadcn can be extended
- No hardcoded colors — use CSS variables from theme
